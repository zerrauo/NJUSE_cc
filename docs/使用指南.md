# Mini Coding Agent 使用指南（零基础版）

> 本文档面向第一次使用本工具的人，按顺序读完并动手操作一遍，就能上手。

## 一、这是什么

一个命令行小工具。你在终端里给它描述一个编程任务，它就会：

1. 自己查看目录里的文件，读懂现状；
2. 自己修改文件、执行命令（比如运行测试）；
3. 出错了自己想办法修正；
4. 最后向你汇报做了什么、怎么验证的。

它背后是一个大语言模型（默认 DeepSeek），核心循环是：**调模型 → 模型说要用什么工具 → 本地执行 → 把结果喂回模型 → 循环，直到模型说"做完了"**。

## 二、第一次使用前的准备（只需做一次）

### 1. 需要什么

- Mac 自带的 Python 3（版本 ≥ 3.9 即可，无需另外安装）
- 一个 DeepSeek API key（到 platform.deepseek.com 注册并充值，几块钱够玩很久）
- 终端（Terminal）

### 2. 进入项目目录

```bash
cd ~/Documents/YAN/NJUSE_projrct_cc
```

### 3. 创建虚拟环境并安装依赖

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

> 虚拟环境（.venv）是一个独立的 Python 运行环境，装的东西不会污染系统。如果提示 pip 版本旧，忽略即可。

### 4. 配置 API key

```bash
cp .env.example .env
```

然后用任意编辑器打开 `.env`，把 `sk-your-key-here` 换成你自己的 key，保存。例如：

```
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx
```

> `.env` 已被 gitignore，绝不会被提交到仓库，放心填。

### 5. 验证安装成功

```bash
.venv/bin/python main.py "创建一个 hello.py 打印 Hello, world!，并运行验证" --workspace /tmp/playground
```

看到它自己写文件、运行、最后输出总结，就说明一切正常。

## 三、基础用法：单次任务模式

格式：

```bash
.venv/bin/python main.py "任务描述" --workspace <工作目录>
```

### 工作区（--workspace）是什么

工作区就是 agent 的活动范围——它**只能读写这个目录里的文件、只能在这个目录里执行命令**。想让它干活，就给它一个目录：

```bash
mkdir -p ~/agent-playground   # 先建一个专门给它玩的目录
.venv/bin/python main.py "写一个随机密码生成器 password.py" --workspace ~/agent-playground
```

> 强烈建议新建一个空目录当工作区，不要直接拿项目本身或重要目录做工作区。

### 运行时你会看到什么

```
  [第 1 轮] list_files({})              ← 它在看目录里有什么
    -> （空目录）
  [第 2 轮] write_file({'path': ...})   ← 它在写文件
    -> 已写入 password.py（xxx 字符）
  [第 3 轮] run_command({'command': ...}) ← 它在运行命令验证
    -> 退出码: 0
============================================================
（最终总结：做了什么、怎么验证的、结果如何）
```

每行 `[第 N 轮]` 就是它的一次工具调用。工具结果只显示第一行，完整内容其实都回传给模型了。

### 任务描述怎么写效果好

- ✅ 好："在 calc.py 里加一个 mul 函数实现乘法，并在 main 里打印 mul(3,4) 的结果，然后运行验证输出是 12"
- ✅ 好："修复 bug：add 命令新增的待办 id 应该从 1 开始而不是 0，修完运行测试验证"
- ❌ 差："帮我搞个计算器"（太模糊，它可能做出和你预期不一样的东西）
- ❌ 差："优化代码"（没说优化什么、怎么算完成）

要点：**说清楚要改什么、期望的结果是什么、怎么验证**。

## 四、交互模式（连续多个任务）

不带任务直接启动：

```bash
.venv/bin/python main.py --workspace ~/agent-playground
```

进入后逐条输入任务，它完成一个你接着输入下一个（**同一个工作区**，前一个任务的成果会保留）：

```
任务 > 写一个 password.py 生成随机密码
（……它开始干活……）
任务 > 在 password.py 里增加 --length 参数
（……继续干活……）
任务 > exit
```

输入 `exit` 或按 Ctrl+C 退出。

## 五、Plan 模式（先看计划再动手）

加上 `--plan`：

```bash
.venv/bin/python main.py --plan "任务描述" --workspace ~/agent-playground
```

流程变成两段：

1. **规划阶段**：模型先输出一份执行计划（第 1 步做什么、第 2 步做什么、怎么验证），**此时它不会碰任何文件**；
2. 你看完计划后选择：
   - 输入 `y` 回车 → 按计划开始执行；
   - 输入 `n` 回车 → 取消，什么都不做。

适合"任务比较重要、想先看看它打算怎么干"的场景。

## 六、只读模式（--readonly）

加上 `--readonly`，agent 就**没有写文件的工具可用**——这不是靠它在任务里自觉，而是代码层面根本不把 `write_file`、`edit_file` 发给模型，想写也写不了：

```bash
.venv/bin/python main.py --readonly "阅读项目代码，说明架构、入口和风险" --workspace ~/agent-playground
```

- 适合：理解陌生代码、代码审查、生成分析报告等"只许看"的任务；
- 你**不需要**在任务描述里写"不要修改任何文件"，flag 本身就是硬保证；
- 它仍然可以运行命令（比如跑测试、运行入口验证行为），遇到想改的地方会给出建议并提示"需要退出只读模式"；
- `--readonly` 可以和 `--plan` 一起用。

## 七、危险命令确认（安全机制）

当它想执行某些危险命令时，会先停下来问你：

```
  [安全确认] 检测到危险命令: rm -rf dist && ls -la
  是否执行？(y/N)
```

- 输入 `y` → 执行；
- 输入 `n` 或直接回车 → 拒绝。**拒绝后它不会放弃，而是会收到"用户拒绝了"的反馈，自动改用更安全的替代方案**（比如把 `rm -rf dist` 改成 `rm dist/旧文件 && rmdir dist`）。

会触发确认的命令（黑名单）：`rm -r` / `rm -rf`（递归删除）、`git reset --hard`、`git push --force`、`git clean -f`、`sudo`、`mkfs`、`dd`、关机/重启命令、fork bomb。普通命令（如 `ls`、`python3 xx.py`、`rm 单个文件`）直接执行，不会问。

## 八、现成的演示脚本（直接跑）

项目里有两个一键演示脚本，跑一遍就能看到 agent 的完整表现：

```bash
./demo/bugfix.sh    # 演示①：修 bug + 加新功能（含 Plan 模式，出现确认时输入 y）
./demo/danger.sh    # 演示②：危险命令拦截（出现确认时输入 n，看它改用安全方案）
```

每次运行都会新建一个全新的演示工作区，不会弄脏你的项目。

## 九、进阶：环境变量调优（可选）

以下配置都在 `.env` 里改，都有默认值，一般不用动：

| 变量 | 默认 | 作用 |
|---|---|---|
| `AGENT_MAX_TURNS` | 30 | 最多允许多少轮工具调用，超过后强制它收尾汇报 |
| `AGENT_MAX_CONTEXT` | 48000 | 对话估算 token 超过该值时，自动把旧历史压缩成摘要 |
| `AGENT_KEEP_RECENT` | 8 | 压缩时原样保留最近的几条消息 |
| `AGENT_BASE_URL` | api.deepseek.com | 换任何 OpenAI 兼容网关（如国内中转、本地模型） |
| `AGENT_MODEL` | deepseek-chat | 换模型名（注意：deepseek-reasoner 不支持工具调用） |

**上下文压缩**在长任务中自动触发，输出里会看到：

```
  [上下文压缩] 消息 10 条 → 摘要 + 最近 6 条
```

这意味着更早的历史被替换成了一段摘要，任务会继续正常进行。

## 十、常见问题排查

| 现象 | 原因与处理 |
|---|---|
| `未找到 DEEPSEEK_API_KEY` | 没建 `.env` 或 key 没填，见第二节第 4 步 |
| 报 `401` 错误 | key 填错或已失效，去 DeepSeek 后台核对 |
| 报 `429` 错误 | 请求太频繁被限流，程序会自动重试几次；还不行就稍等再跑 |
| 一直卡着没输出 | 在等模型响应，正常；等不及按 Ctrl+C 中断 |
| 模型反复用 `python` 报退出码 127 | 正常现象：macOS 没有 `python` 命令只有 `python3`，它通常会自己发现并改用 `python3` |
| 想换模型 | 改 `.env` 里的 `AGENT_BASE_URL` 和 `AGENT_MODEL` |

## 十二、练习任务清单（按难度排序）

上手后可以拿这些任务练手，工作区都用 `~/agent-playground`：

1. 写一个 `fizzbuzz.py`：打印 1 到 100，3 的倍数输出 Fizz，5 的倍数输出 Buzz，同时是 3 和 5 的倍数输出 FizzBuzz，运行验证前 20 个输出。
2. 写一个 `wordcount.py`：统计文本文件里每个单词出现次数，并让它自己造一个测试文件验证。
3. 写 `guess.py` 猜数字游戏，然后让它**给自己写的游戏写测试**。
4. 先手动写一个有 bug 的小程序放进工作区，再让它修 bug（描述 bug 现象，别说原因，看它怎么排查）。
5. 让它给一段代码加注释并解释这段代码在干什么（观察它 read_file 后直接回答、不调用其他工具）。
6. 用 `--plan` 跑任务 4，对比有计划和没计划的行为差异。
7. 故意让它"删除工作区里某个目录"，体验危险命令确认的拦截与它改用安全方案的过程。
8. 用 `--readonly` 让它分析一个项目并"顺手把发现的问题修掉"——观察它如何给出修复建议但拒绝动手。
